BPMN 2.0 for the RavenRS diagram components, as data and functions only: the components are the library’s own, and this crate hands them what BPMN is.

  • notation is BPMN as a FlowNotation: its elements grouped for a palette, how tasks look, which connections may be made and how each is drawn (sequence, association, message), what comes next from the keys, the checks of a process and the BPMN XML format. Give it to FlowCanvas, FlowToolbox, FlowInspector and FlowLibrary.
  • xml writes a process as BPMN 2.0 XML with its drawing (BPMNDI) and reads what other tools write, elements, lanes, labels and bend points included.
  • rules says what is wrong with a process.
  • plan is what a local model is asked, and how its answer becomes a process: the model only writes a small plan the app checks, never the XML.

Words shown are in Brazilian Portuguese.

use ravenrs_reactive::State;
use ravenrs_widgets::{FlowCanvas, FlowGraph, FlowToolbox};

let bpmn = ravenrs_flow_bpmn::notation();
let graph = State::new(ravenrs_flow_bpmn::example_process());
let canvas = FlowCanvas::new(graph.binding()).notation(&bpmn);
let palette = FlowToolbox::new().notation(&bpmn);
let file = ravenrs_flow_bpmn::xml::to_xml(&graph.get(), "Compra");
assert!(file.contains("<bpmn:process"));

Modules§

elements
The elements of BPMN 2.0 as nodes and connections of a FlowGraph: each node’s kind is the element’s name in the XML (task, exclusiveGateway), each connection’s kind is empty for a sequence flow, or association or messageFlow.
plan
What is asked of the local model, and how its answer becomes a process. The model only writes a plan in a small JSON; the app checks it, builds the elements and lays them out, so a model never writes BPMN, and an answer that is not a plan changes nothing.
rules
What makes a process well formed, said in words people read: checked on the whole diagram when asked, and on each connection as it is made.
xml
BPMN 2.0 XML: a diagram written with its process and its drawing (BPMNDI), and read back from any tool that writes the same.

run_rules
How a process runs: a token leaves each start event, passes tasks, chooses one way at an exclusive gateway and one or more at an inclusive one (whose join waits only for the ways taken), waits for every way and splits at a parallel one, and stops at an end; it follows sequence flows only.
