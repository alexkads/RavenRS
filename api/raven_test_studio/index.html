Raven Test Studio, first step (#634, part of #627).

A scenario is a flow of blocks: open the app, type, click, check. The Studio runs it with ravenrs-e2e against an app, marks each block as it goes (done, failed with the error, or not run), and keeps a log of the run. Everything on screen is a RavenRS component: FlowLibrary keeps the scenarios, FlowToolbox has the blocks, FlowCanvas shows the scenario and FlowInspector edits the selected block.

For now the app under test is a small form that comes with the Studio (sample::expense_app) and runs in the same process. Opening the person’s own app in another process, scenario files and the live preview come in the next steps of #627.

The Studio is tested by the tool it is made of: its tests drive it with ravenrs-e2e, as tests/suite/self_test.rs shows.

Modules§

apps
The apps a scenario opens apart, from ravenrs-e2e-runner, and Raven Finanças, which the Studio knows by the declaration in its own Cargo.toml, read when the Studio is built, so the installed Studio opens the installed app with no checkout.
atualizacao
Whether there is a newer Studio, for whoever asks with no window: a person at the command line, or the pane beside a Claude conversation. The answer is the one the window’s status bar gives, from the same rule of ravenrs-app-update.
cache
The Studio’s own cache of runs, so a scenario that did not change, on a build that did not change, is not run again: its report comes back at once, saying it came from the cache.
delegate
Handing a scenario to a coding agent: the Studio asks Codex (or Claude), with the cheapest model and reading only, to run the scenario through the Studio’s own command line, read the report and, when it failed, find the cause in the Rust sources. Then the Studio runs the same scenario itself and says whether the agent’s verdict is the one it found, so a delegated answer is never taken on trust.
project
A Rust project the Studio is pointed at, read by ravenrs-e2e-runner without building it.
report
What a run tells whoever asked for it, from ravenrs-e2e-runner, plus the report of a run of the Studio’s diagram.
runner
What each block of a scenario does, and running it with ravenrs-e2e.
sample
The apps the first scenarios run against, and the scenarios that come with the Studio.
suggest
Scenarios written by an AI for an app of a project the Studio was pointed at: when the app has none, and to suggest others it does not have yet.
tray
The Studio’s menu beside the clock (#643): how its own test went, a button that runs it again with the window closed, and an update that is ready.
versao
Who the Studio is to the installer and the updater of ravenrs-app-update, the same that install and update Raven Finanças and Raven Flows: its name, folders and addresses.

Constants§

KINDS
The kinds of block, with the word the canvas and the inspector show for each.
SCENARIOS
What --run takes by name. A Studio installed from scratch brings no test scenarios: only its own health check, “O Studio testa o Studio”, and financas, which runs the scenarios Raven Finanças brings in its own tests/e2e/. Any other scenario is a .raventest file, kept in the app or in a QA team’s folder, and run by path (run_named).
VERSION
The Studio’s version, the one its news speak of.

app

app_delegating
The Studio opening scenario, handing it to agent when “Delegar” is pressed: Claude instead of Codex, or a fake agent in tests.
app_icon
The Studio’s icon, for the window and the icon beside the clock.
app_in_tray
The Studio as installed_app_in_tray opens it, with an updater that does nothing until told, for tests of the menu beside the clock.
app_with
The Studio opening scenario, keeping its scenarios in storage, not looking for updates.
installed_app
The Studio as its window opens: it tests itself, then looks for a new version when it opens and every hour after, as Raven Finanças does.
installed_app_in_tray
installed_app, keeping link’s menu beside the clock as the window’s state changes and acting on what is chosen there.
open
Opens the app an Open block names: the sample form, another Studio with the sample scenario, or another Studio whose scenario fails on purpose, compiled in; or an app opened apart in a child process, such as Raven Finanças (apps). A Studio opened here runs its own scenario the same way, so the Studio can test the Studio.
run_bundled
Runs a scenario that comes with the Studio, with no window, and reports it; None when there is no scenario by that name. With a cache, a scenario that did not change on a build that did not change comes back from it instead of running again.
run_bundled_kept
run_bundled_with, also giving the window left open at the end, when the run keeps it. A run with the window runs again, since the person wants to see it.
run_bundled_with
run_bundled as options say: filming, and where to keep the films. A run that films runs again, since the cache keeps no film.
run_files
Runs .raventest files with no window and reports them: one file, or every file of a folder (the QA team’s own, or an app’s tests/e2e/), one after the other.
run_files_kept
run_files_with, also giving the window left open at the end, when the run keeps it.
run_files_with
run_files as options say. The files are read as cargo ravenrs e2e reads them, and run on the Studio’s diagram, which opens the apps compiled into the Studio too.
run_named
Runs what name says: a name of SCENARIOS, or the path of a .raventest file or of a folder of them. Err says why nothing ran.
run_named_kept
run_named_with, also giving the window left open at the end, when the run keeps it.
run_named_with
run_named as options say.
self_checked_app
The Studio after testing itself, with no window: it runs “O Studio testa o Studio” before it opens (from cache when neither the scenario nor the build changed) and says how it went in its status bar, so a Studio that no longer works says so before anyone trusts it.
served_app
The Studio another Studio drives over the test channel (--e2e-serve): the sample scenario to run, step and stop, and its own health check in the status bar, as its window shows it. It brings no scenario of its own and does not look for updates.
