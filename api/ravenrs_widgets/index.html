Declarative views and the UI runtime.

§Writing components

There are three ways to make your own component, from simplest to most powerful:

  1. A function returning impl View, composing existing views. Good for stateless pieces of UI.
  2. A Component: a struct holding its state (State fields, bindings, callbacks) with a body() that composes views. This is the SwiftUI-style building block and covers most needs.
  3. A View implemented directly: full control over layout boxes, painting (including arbitrary Scene drawing through Paint::Custom), hit-testing, focus and click handling via BuildCx. The built-in widgets are written this way, with no private API.

Canvas is the shortcut for custom drawing inside a normal layout.

§Features

  • decode (default): PNG and JPEG decoding for Image::from_bytes.
  • charts (default): Chart, BarChart, AreaChart and Barcode. They draw the same charts and codes as reports, through ravenrs-graphics.

§Runtime

Ui owns the root view and turns it into a Scene: build (views to elements, tracked by a reactive observer), layout (Taffy), paint. It only rebuilds when state the last build read has changed or the interaction state (hover, press, focus) changed, and it never touches the GPU.

§Motion

A view declares how a node moves with BuildCx::motion and the runtime plays it. While only animations run, frames repeat the paint phase alone, so views are not rebuilt. When nothing moves, no frames are requested.
