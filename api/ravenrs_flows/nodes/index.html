Module nodes 

Source
Expand description

The built-in kinds: a manual start, branches, merges, a loop in batches, and the nodes that set, filter, sort, group, split and join items. Conditions and values are written in the criteria language ([paid] = true, [qty] * [price]) and read each item’s JSON. Above run, plan, catalog and item; nothing in the crate uses it, so an app may leave it out.

Structs§

Batches
A loop over its input in batches of size (1 by default). Each turn it sends the next batch to batch, which leads to the loop’s body; what the body sends back reaches its input back. When no batch is left, it gives everything that came back on done.
Delay
Waits ms milliseconds in a way that outlives the app: the run stops at this node and a durable run starts it again when the time comes, then the items pass on. Run without one, the run just ends waiting (RunOutcome::Waiting).
Filter
Keeps the items whose condition is true on main, unchanged; the others go to discarded.
Group
One item per group of items with the same values of the fields in by (one group of all with none), in the order each group first appears. Its parameter aggregates lists { "field": …, "op": "sum" | "count" | "min" | "max" | "avg" | "list", "as": … }.
If
Sends each item to true or false by its parameter condition. A side no item takes gives nothing, so a merge after it goes on with the other.
Join
One item holding a list of all that came: the whole items, or only their field, under the name as (items by default).
Manual
Starts a run with the items of its parameter items, a list; one empty item without it.
Merge
Joins the items of its inputs a and b, by its parameter mode:
Set
Sets fields on each item: its parameter fields maps each name to an expression worked out over the item. With keep_only, the item keeps only those fields.
Sort
Puts the items in order by the fields of its parameter by: a list of field paths, or of { "field": …, "descending": true }. Items that tie keep the order they came in.
Split
One item per entry of the list in each item’s field: an object entry is the new item, any other is kept under the field’s name. An item whose field is not a list goes to the error output.
Subflow
Runs another flow with the items that came, and gives what it ends with. Its parameter flow names one of the flows it was made with; input names the node of that flow that starts with the items (its first trigger by default) and output the node whose first output it gives (the last to run by default). The flow it calls stops when this one is cancelled, and has only the time this node has left.
Switch
Sends each item to the output named after the text of its value, one output per entry of cases; an item matching no case goes to otherwise.
Wait
Waits ms milliseconds on the run’s clock, then passes its items on. It stops early when the run is cancelled or its time is up. The wait is in memory: a wait that outlives the app needs a durable run.
WaitEvent
Waits for the event named by its parameter event (an approval, a reply, a webhook), then gives the items the event brought. The run stops here until a durable run is told of it.
