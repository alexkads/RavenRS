Raven Code: a small editor for Rust projects, built on the DockArea. It opens a project from disk, edits and saves its files, and builds and runs it with cargo, with the compiler’s errors marked in the code and listed under Problems. It is the start of an IDE for RavenRS.

cargo run -p raven-code -- <folder> opens a project; with no folder it opens a copy of a small sample project in a temporary folder, so the repository is never edited.

  • project: the project on disk: its files, making, renaming and deleting them, and searching them.
  • cargo: building, running, testing and checking it, stopping it and typing into it, and reading what the compiler says.
  • lsp: what rust-analyzer says while typing: problems, suggestions, tips, definitions.
  • config: what is remembered between runs: the recent projects and how each was left.
  • app: the window, wiring them to the components.

Keys, with Cmd for Ctrl on a Mac: Ctrl+S saves the file at the front, Ctrl+O opens a folder, Ctrl+B builds, F5 runs and Shift+F5 stops, Ctrl+Shift+T tests, Ctrl+Z undoes, Ctrl+F finds in the file and Ctrl+H replaces, Ctrl+Shift+F searches the project, Ctrl+Space suggests, F12 goes to a definition, and Ctrl+Tab goes back to the panel used before.

Modules§

app
The window: the files and the search at the left, the open files in the middle, the terminal and the problems below, a toolbar and a status bar. It holds the state and wires the project, cargo, lsp and config parts to the components; what they do is in them.
cargo
Building and running the project with cargo, on a thread of its own, and reading what the compiler says. The reading is apart from the running, so it is tested with no cargo at all.
config
What Raven Code remembers between runs, in the user’s folder of settings: the projects opened last, and how each project was left (the arrangement of the window, the open files and where their carets were). Nothing is written inside the projects. Tests give it a folder of their own with Config::at.
lsp
Talking to a language server (rust-analyzer) over the Language Server Protocol: what is wrong while typing, suggestions, tips and where things are defined. It speaks JSON-RPC over any pair of streams, so tests talk to a fake server through pipes, with no rust-analyzer.
project
The project on disk: what is in it, and reading and writing its files. Nothing here knows about the screen, so it is tested with a folder and no window.
