pub fn clock(&self) -> f64

The session’s clock, in seconds since it started. It moves only when the session moves it: with Self::advance, and while a step waits.

Source

pub fn advance(&mut self, seconds: f64)

Moves the clock seconds forward one frame at a time, as a platform would: animations run to where they would be by then, and timers that come due fire. Without it, the session never starts an animation, and what a screen shows “after a moment” never shows.

Source

pub fn wait_until( &mut self, timeout: Duration, check: impl FnMut(&mut Self) -> E2eResult, ) -> E2eResult

Looks at the screen until check passes, moving the clock with real time between looks, so timers fire and work done in the background (which wakes the screen) shows. When timeout runs out, it fails with ErrorCode::Timeout and what the last look found.

Source

pub fn patiently( &mut self, patience: Duration, step: impl FnMut(&mut Self) -> E2eResult, ) -> E2eResult

Like Self::wait_until, but only for a failure waiting may still fix (E2eError::may_pass_later), and when time runs out it fails as the step itself failed, with the same code. It is how a tool runs a step without making the person who writes it think about time.

pub fn for_window() -> Self

A session with no interface of its own, to drive the interface of a real window with Self::in_window: what an app opened with a test tool’s --headed does, so the steps of a scenario act on what the person sees. Until then it holds an empty screen.

Source

pub fn in_window<R>( &mut self, ui: &mut Ui, now: f64, steps: impl FnOnce(&mut Self) -> R, ) -> R

Runs steps on ui, the interface a window shows, whose clock reads now seconds: the session borrows it for the steps and gives it back, so every click, key and check of Self::for_window lands on the window, and its clock, size and references to parts of the screen carry on from one call to the next. Waiting steps hold the window’s thread while they wait, as they hold the test’s in a session with no window.
