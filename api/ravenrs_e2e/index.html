End-to-end tests for RavenRS apps.

An E2e session runs a view with no window, the way the app runs on screen, and lets a test find a part of the screen, act on it and check it:

use ravenrs_core::Role;
use ravenrs_e2e::{E2e, E2eResult, Query};
use ravenrs_style::Theme;

fn saving_works() -> E2eResult {
    let mut e2e = E2e::new(screen(), Theme::raven_dark());
    e2e.by_test_id("save").click()?;
    e2e.locate(Query::role(Role::Status)).expect().to_have_name("Saved")?;
    Ok(())
}

The parts are found in the accessibility tree, the same one screen readers read: by the id the app declared with ViewExt::test_id, by role and name, or by the text shown. Actions are real input events at the middle of the part, so they go through the same path as a person’s, and a part that is disabled, hidden or covered by something else fails instead of being clicked anyway. Every failure carries a stable ErrorCode, what was on the screen, and up to three nodes that came close.

E2e::snapshot writes the screen as text, one line per node with its role, name, test id, value and states and a [ref=eN] that stays the same for the whole session. It is how a test, a report or a coding agent sees the screen without an image. Secret values never appear in it.

Time is the session’s: it moves only with E2e::advance and while a step waits, so an animation or a timer never makes a test pass on one machine and fail on another. E2e::wait_until looks again until a check holds, moving the clock with real time so timers fire and work done in the background shows, and fails with ErrorCode::Timeout when it does not; E2e::patiently is the same for a step that should simply not fail for being early.

Besides clicks and keys, a Locator fills a field (Locator::fill), picks an option (Locator::select), opens and closes an item (Locator::expand, Locator::collapse) and scrolls a part into sight (Locator::scroll_into_view), even a row a long list has not built yet. Lists, grids and trees with keys give their rows the test ids row:<key> and item:<key>, which stay with the data when it moves.

Structs§

E2e
A view running with no window, driven by a test. See the crate documentation.
E2eError
A failed step: its code, what happened, how to fix it, what came close and the screen as it was, so the failure explains itself without running the test again.
Expect
Checks on what a Locator finds; each one fails with ErrorCode::Expectation and the screen when it does not hold.
Locator
What a Query finds in a session, to act on or check. Made by E2e::locate and its shorthands; each action finds the node again, on the screen as it is at that moment.
Query
What a test looks for: a node of the accessibility tree, by the id the app declared, by role and name, by the text it shows or by its reference in a snapshot. Narrow it with Query::name, Query::within and Query::nth.
