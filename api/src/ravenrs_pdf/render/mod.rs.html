1//! pdfcraft-render — page rasterization and document inspection.
2//!
3//! **Bootstrap status (see ADR-0004):** rasterization goes straight through the `hayro` crate
4//! (hayro-interpret + vello_cpu). Inspection uses the lazy `cos` reader with a read-only lopdf
5//! object adapter and retains `lopdf` loading for compatibility repairs. The renderer and that
6//! adapter are replaced by `model` and the DisplayList design in M1–M2. The public API is what the engine and UI rely on, so
7//! the swap stays internal to this crate.
