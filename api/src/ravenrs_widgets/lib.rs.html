1//! Declarative views and the UI runtime.
2//!
3//! # Writing components
4//!
5//! There are three ways to make your own component, from simplest to most powerful:
6//!
7//! 1. **A function** returning `impl View`, composing existing views. Good for
8//!    stateless pieces of UI.
9//! 2. **A [`Component`]**: a struct holding its state ([`State`](ravenrs_reactive::State)
10//!    fields, bindings, callbacks) with a `body()` that composes views. This is the
11//!    SwiftUI-style building block and covers most needs.
12//! 3. **A [`View`]** implemented directly: full control over layout boxes,
13//!    painting (including arbitrary [`Scene`](ravenrs_core::Scene) drawing through
14//!    [`Paint::Custom`]), hit-testing, focus and click handling via [`BuildCx`].
15//!    The built-in widgets are written this way, with no private API.
16//!
17//! [`Canvas`] is the shortcut for custom drawing inside a normal layout.
18//!
19//! # Features
20//!
21//! * `decode` (default): PNG and JPEG decoding for [`Image::from_bytes`].
22//! * `charts` (default): `Chart`, `BarChart`, `AreaChart` and `Barcode`. They draw
23//!   the same charts and codes as reports, through `ravenrs-graphics`.
24//!
25//! # Runtime
26//!
27//! [`Ui`] owns the root view and turns it into a [`Scene`](ravenrs_core::Scene):
28//! *build* (views to elements, tracked by a reactive observer), *layout* (Taffy),
29//! *paint*. It only rebuilds when state the last build read has changed or the
30//! interaction state (hover, press, focus) changed, and it never touches the GPU.
31//!
32//! # Motion
33//!
34//! A view declares how a node moves with [`BuildCx::motion`] and the runtime
35//! plays it. While only animations run, frames repeat the paint phase alone, so
36//! views are not rebuilt. When nothing moves, no frames are requested.
