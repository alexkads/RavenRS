1//! Runs flows drawn on a RavenRS `FlowCanvas`.
2//!
3//! A flow ([`FlowDefinition`]) is a list of nodes, each of a kind at a version with its
4//! parameters, and connections between their named ports. A [`Catalog`] holds the kinds: what
5//! each one says about itself ([`NodeSpec`]) and the code that runs it ([`NodeKind`]). A
6//! [`Plan`] checks a flow against the catalog and puts its nodes in order, and an [`Executor`]
7//! runs it, passing lists of [`Item`]s from node to node: the whole flow, from one node on
8//! (reusing an earlier run's items upstream), or one node alone. Every item says where it is
9//! and what it was made from, and the same flow, items and clock always give the same run.
10//!
11//! No screen and no GPU: the crate runs on a server or a worker thread. The bridge to the
12//! canvas ([`FlowDefinition::to_graph`], [`FlowDefinition::from_graph`] and
13//! [`Catalog::run_rules`]) speaks the `ravenrs-graphics` model the `FlowCanvas` draws.
14//!
15//! ```
16//! use ravenrs_flows::{
17//!     Catalog, Executor, FixedClock, FlowDefinition, Item, NodeContext, NodeDef, NodeError, NodeKind,
18//!     NodeSpec, Plan, Ports,
19//! };
20//! use serde_json::json;
21//!
22//! /// Starts a run with the items of its parameter `items`.
23//! struct Manual;
24//! impl NodeKind for Manual {
25//!     fn spec(&self) -> NodeSpec {
26//!         NodeSpec::new("manual", 1).title("Manual start").output("main").trigger()
27//!     }
28//!     fn execute(&self, cx: &NodeContext<'_>) -> Result<Ports, NodeError> {
29//!         let items = cx.parameter("items").and_then(|v| v.as_array()).cloned().unwrap_or_default();
30//!         Ok(Ports::from([("main".into(), items.into_iter().map(Item::new).collect())]))
31//!     }
32//! }
33//!
34//! /// Keeps the items whose `paid` is true.
35//! struct Paid;
36//! impl NodeKind for Paid {
37//!     fn spec(&self) -> NodeSpec {
38//!         NodeSpec::new("paid", 1).input("main").output("main")
39//!     }
40//!     fn execute(&self, cx: &NodeContext<'_>) -> Result<Ports, NodeError> {
41//!         let kept = cx.input("main").iter().filter(|i| i.get("paid") == Some(&json!(true))).cloned();
42//!         Ok(Ports::from([("main".into(), kept.collect())]))
43//!     }
44//! }
45//!
46//! let catalog = Catalog::new().with(Manual).with(Paid);
47//! let flow = FlowDefinition::new("f1", "Paid orders")
48//!     .node(NodeDef::new("start", "manual").parameter("items", json!([{"paid": true}, {"paid": false}])))
49//!     .node(NodeDef::new("filter", "paid"))
50//!     .connect("start", "main", "filter", "main");
51//!
52//! let plan = Plan::compile(&flow, &catalog).expect("a flow the catalog knows");
53//! let run = Executor::new(&plan, &catalog).clock(FixedClock(0)).run();
54//! assert_eq!(run.output("filter", "main").len(), 1);
55//! // The item kept says it came from the first item of the start.
56//! assert_eq!(run.output("filter", "main")[0].from[0].index, 0);
57//! ```
58//!
59//! The built-in kinds are in [`nodes`], all at once in [`Catalog::builtin`]: a manual start,
60//! `if`, `switch`, `merge` (append, by position, by key, first), a loop in batches, and the
61//! nodes that set, filter, sort, group, split and join items. Their conditions and values are
62//! written in the criteria language of `ravenrs-criteria`. A loop node goes round its body
63//! while it sends items into it ([`NodeContext::iteration`], [`Plan::loop_body`]), and items
64//! that fail one by one go to every node's error output, [`ERROR_PORT`].
65//!
66//! A run can be cancelled from any thread ([`CancelToken`], [`Executor::cancel_with`]), has
67//! time limits for each node and for the whole run, and tries a node again as its [`Retry`]
68//! says, by the kind of [`Failure`]: a call whose answer was lost is not repeated until
69//! [`NodeKind::reconcile`] says it did not happen. Waits run on the run's [`Clock`];
70//! [`ManualClock`] makes them take no time in tests.
71//!
72//! A durable run hears each step ([`Executor::on_step`]) and goes on from it
73//! ([`Executor::resume`]); `ravenrs-flows-runtime` does this on SQLite, and runs the nodes that
74//! wait for a time or an event (`delay`, `wait_event`) again when they are due.
75//!
76//! Not here yet: the schema of a kind's parameters (#530).
