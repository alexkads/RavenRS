1//! The serial protocol of the Brazilian pinpad, as defined by ABECS, version 2.20.
2//!
3//! In layers: [`quadro`] (packets and CRC) and [`comandos`] (commands and responses) do no input or
4//! output; [`sessao`] adds the flow of the link with time passed in as a value; [`driver`] offers
5//! calls over any [`PortaPinpad`]; [`simulado`] is a pinpad in memory and, with the `serial`
6//! feature on native targets, `serial` is a real port.
7//!
8//! This is what a point-of-sale software may do with no key from an acquirer: show text and images,
9//! ask for a value from the fixed table, offer a menu, read a key. **There is no PIN capture and no
10//! card reading here, on purpose.** Those need the keys and tables of an acquirer network, and on a
11//! real checkout they stay with the TEF software, which also owns the port while it runs.
12//!
13//! Written from the public specification and checked against its packet examples. It was never
14//! connected to a real pinpad. The specification carries a notice restricting copies, so this crate
15//! does not embed it nor its long text tables; see `docs/PAGAMENTOS.md`.
16
