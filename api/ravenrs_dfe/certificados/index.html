Module certificados 

Source
Expand description

Laboratory certificates in the ICP-Brasil format, so production code runs unchanged here.

Every certificate is issued by a test authority whose name says what it is: RAVENRS SANDBOX AC - SEM VALOR. None of it has fiscal value, and it cannot leave the laboratory: Ambiente::Homologacao and HttpTransport refuse a certificate from this authority, and the sandbox refuses any other.

§Format

CN as RAZAO:CNPJ, and otherName entries 2.16.76.1.3.4 (data of the person responsible), 2.16.76.1.3.2 (name of that person), 2.16.76.1.3.3 (CNPJ) and 2.16.76.1.3.7 (CEI). The MOC 7.0 confirms the CNPJ and CPF entries; the others are in REGRAS.md with their source and trust.

§Keys

The certificates are issued at run time, but AcTeste::padrao and the holders use RSA keys bundled in fixtures/laboratorio, public on purpose, because generating RSA takes seconds per key in a debug build. AcTeste::gerar and GeradorCertificado::com_chave_gerada really generate one, from a seed, with no random source, so they work in WebAssembly.

§A real token

TokenSimulado stands behind Signer, which is the same contract a real A3 will use. A real token needs PKCS#11, which is foreign code, forbidden in this workspace. It will run in a helper process, not implemented here, speaking JSON Lines on stdin and stdout:

-> {"op":"slots"}                                  <- {"slots":[{"id":0,"rotulo":"..."}]}
-> {"op":"entrar","slot":0,"pin":"..."}            <- {"ok":true} | {"erro":"pin","restantes":2}
-> {"op":"certificado","slot":0}                   <- {"der_base64":"..."}
-> {"op":"assinar","hash":"sha1","dados_base64":"..."}  <- {"assinatura_base64":"..."}
-> {"op":"sair"}                                   <- {"ok":true}

The private key never crosses this pipe, and the PIN never reaches a log.
