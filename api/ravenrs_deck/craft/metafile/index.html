Module metafile 

Source
Expand description

Windows metafiles: reads Windows Metafiles (WMF), Enhanced Metafiles (EMF) and EMF+ into a neutral vector model, and (feature write) writes EMF and WMF.

parse plays a file’s records on a model of the device context and returns a Picture: filled and stroked paths with their line styles, pattern fills, RGBA bitmaps and text strings, each with the clip it was drawn under, in a picture frame with y down. Nothing in the model belongs to an application: mapping it onto a document (or drawing it) is the caller’s. Picture::place fits a picture into a rectangle for callers that draw it.

Text stays font-agnostic: a Text item names the font the file asks for and carries the string, its advances and alignment; the caller resolves the font and draws the glyphs.

The reader is pure Rust over byte slices (no file system), so it builds for wasm. Every read is bounds-checked and every count is capped; hostile input yields a shorter picture or an Error, never a panic. Records follow MS-WMF, MS-EMF and MS-EMFPLUS; the README lists the records read and the limits. Records of a type the reader does not know are counted in Picture::skipped_records.

bez_path
Segments as a kurbo path. A segment after a close opens a new subpath at the last start point.
crop_window
The part of a picture’s source that crop (left, top, right, bottom fractions of the source) keeps, as fractions of the source: [left, top, width, height], bitmap or metafile alike. Each side is taken as 0–1 (junk as 0). A negative side pads the source instead of cutting it (down to -100), as a negative a:srcRect side does in Office files and a picture fitted whole into a frame of another shape needs: the window then starts before the source or ends past it. When the two sides of an axis leave less than 0.5% of it, the left (top) side stands and 0.5% shows.
