The folders automation may read and write.

deckcraft-cli mcp --automation-read-root <dir> --automation-write-root <dir> confines the files an agent’s commands reach. AutomationRoots holds the two folders. While they are in force, every path a command reads goes through check_read and every path it writes through check_write:

  • The path is made absolute against the working directory, as the file system reads it. Its links are followed: for a file that doesn’t exist yet, the links of its nearest existing folder, the rest of the path being plain names (.. below a missing folder is refused, and so is a link that leads nowhere).
  • The result must lie inside the root, compared by whole components (/work2 isn’t inside /work), exactly: on Windows what exists is resolved to its real case first.
  • Read and write access are separate: a root given alone grants only its own kind of access.

Roots are in force on a thread inside confine, and in the whole process after confine_process (deckcraft-cli mcp), except inside unconfined. Without roots nothing is checked.

A path is checked, then opened: a process that can change the folders in between (swapping in a link) can still win that race. The roots keep an agent to the files it was given; they don’t guard against other programs on the computer.
