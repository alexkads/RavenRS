Module recovery 

Source
Expand description

Crash recovery (PowerPoint’s AutoRecover): unsaved changes of every open presentation are written to a recovery folder (file.recovery.save, called on a timer by the app and after a command panics); saving or closing a presentation removes its entry; after a crash file.recovery.open reopens what was left there as unsaved presentations that remember where they were saved.

An entry is <uid>.deckcraft (the presentation) plus <uid>.json ({"path", "title", "saved", "owner"}: the original file, the title, when it was written (Unix seconds) and the instance that owns it).

Several instances share the folder. Document uids are unique across processes, each instance holds a lock on owner-<instance>.lock while it runs, and file.recovery.open leaves alone the entries of an instance whose lock is still held. Opening an entry doesn’t delete it: the recovered presentation keeps the entry’s uid, so the snapshot stays on disk until the next recovery save replaces it or a save of the presentation removes it.

Constants§

MAX_REOPEN
Presentations reopened per start; the rest stay on disk for the next one, so a folder full of entries can’t stall start-up.

list
Entries in dir: (uid, metadata).
open
Reopen every entry left by an instance that is no longer running as an unsaved presentation. Entries stay on disk, now owned by this instance: the presentation keeps the entry’s uid, so the next recovery save replaces the snapshot and saving or closing it removes it. Entries of a running instance, unreadable entries and entries already open here are left alone. Returns the opened documents’ indices. At most MAX_REOPEN are opened per start, the newest first; the rest wait for the next one.
save
Write entries for the unsaved presentations (and drop those of saved ones). Returns how many were written.
