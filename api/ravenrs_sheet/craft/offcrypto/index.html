Clean-room Office document cryptography, written from Microsoft’s public Open Specification [MS-OFFCRYPTO]: Office Document Cryptography Structure and ECMA-376.

A password-encrypted .docx, .xlsx or .pptx is not a zip but a compound file ([MS-CFB], read and written with craft-cfb) holding EncryptionInfo (how the key comes from the password) and EncryptedPackage (the zip, AES encrypted). This crate goes between the two: file bytes in, package bytes out, and back. It knows nothing about what the package holds.

  • is_encrypted tells such a file from any other compound file; check says, without a password, whether a password could open it.
  • decrypt reads agile encryption (Office 2010 and later: AES-CBC in 4096-byte segments, SHA-1 to SHA-512, a password verifier and an HMAC over the encrypted stream, which is required and checked) and standard encryption (Office 2007: AES-ECB, SHA-1). RC4, extensible, certificate-only and rights-managed files are refused by name (Error::Unsupported).
  • encrypt writes agile encryption as Office does: AES-256, SHA-512, 100,000 spins.
  • protection has the password hashes of document, sheet and workbook protection.

Files are hostile: every stream read is capped, every length is checked before slicing, and the spin count is bounded by the specification’s maximum (10,000,000). Passwords and keys are wiped from memory when dropped and never logged.

let package = b"PK\x03\x04 a zip package";
let file = ravenrs_sheet::craft::offcrypto::encrypt_with_spin_count(package, "secret", 1000)?;
assert!(ravenrs_sheet::craft::offcrypto::is_encrypted(&file));
assert_eq!(ravenrs_sheet::craft::offcrypto::decrypt(&file, None), Err(ravenrs_sheet::craft::offcrypto::Error::PasswordRequired));
assert_eq!(ravenrs_sheet::craft::offcrypto::decrypt(&file, Some("guess")), Err(ravenrs_sheet::craft::offcrypto::Error::WrongPassword));
assert_eq!(ravenrs_sheet::craft::offcrypto::decrypt(&file, Some("secret"))?, package);

Modules§

protection
Protection passwords: the hashes that guard turning document, sheet or workbook protection off ([MS-OFFCRYPTO] §2.4.2.4, the ISO write-protection method; ECMA-376 Part 1 §17.15.1.29 and §18.2.29; Part 4 §14.8.1 for the legacy form). Protection isn’t encryption: the file stays readable, the password only guards the setting.

Functions§

check
Whether the right password could decrypt this file, checked without one: an error names a scheme no password opens here (Error::Unsupported) or damage, so a caller can say so instead of asking for a password first.
check_password
Refuse a password Word wouldn’t accept: empty, or longer than MAX_PASSWORD_CHARS.
decrypt
The zip package inside an encrypted Office file. Without a password (None) this says Error::PasswordRequired once it knows the file is one it can decrypt; a password that doesn’t fit gives Error::WrongPassword.
decrypt_streams
decrypt from the contents of the two streams.
encrypt
Encrypt a zip package with password (agile encryption: AES-256-CBC, SHA-512, Word’s spin count), as Word’s “Encrypt with Password” does.
encrypt_with_spin_count
encrypt with a chosen spin count (tests use a small one; files should use the default).
is_encrypted
Is this an encrypted Office package (a compound file with an EncryptedPackage stream) rather than a zip? A rights-managed file counts: it has the stream but no EncryptionInfo, and decrypt names it as unsupported.
