Module protection 

Source
Expand description

Protection passwords: the hashes that guard turning document, sheet or workbook protection off ([MS-OFFCRYPTO] §2.4.2.4, the ISO write-protection method; ECMA-376 Part 1 §17.15.1.29 and §18.2.29; Part 4 §14.8.1 for the legacy form). Protection isn’t encryption: the file stays readable, the password only guards the setting.

The values are the attribute values as files hold them (base64 text, decimal spin count); which attributes carry them (w:hashValue, hashValue, w:hash, …) is the format’s.

Functions§

check_legacy_password_hash
Does password match a stored hash of the legacy form (cryptAlgorithmSid, hash, salt, cryptSpinCount; ECMA-376 Part 4 §14.8.1)? The password first becomes Word’s legacy 32-bit key (legacy_key), whose bytes, reversed and written as an upper-case hex string, are hashed like a password. algorithm_sid is 4 (SHA-1), 12 (SHA-256), 13 (SHA-384) or 14 (SHA-512); the older MD2, MD4 and MD5 are PasswordCheck::Unsupported.
check_password_hash
Does password match a stored hash of the current form (algorithmName, hashValue, saltValue, spinCount)? The algorithm is SHA-1, SHA-256, SHA-384 or SHA-512 (with or without the dash); a missing salt is empty and a missing spin count is 0. Anything else, a spin count above 10,000,000 or damaged values are PasswordCheck::Unsupported, never a match.
hash_password
Hashes a new protection password. The spin count is capped at 10,000,000; an empty or over-long password is refused (check_password).
legacy_key
Word’s legacy 32-bit password key (ECMA-376 Part 4 §14.8.1): the password as UTF-16 without a leading BOM, cut to 15 characters, each character reduced to one byte (its low byte, or its high byte when the low byte is 0); the high-order word comes from the initial code array and the encryption matrix, the low-order word from rotating and XOR-ing the bytes backwards.
