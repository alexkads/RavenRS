Open Packaging Conventions (ECMA-376 Part 2): the ZIP container that DOCX, XLSX and PPTX files share.

  • Package inflates every part up front, within Limits. LazyPackage indexes the archive and inflates a part when it is asked for, against a running total.
  • Rels and ContentTypes read _rels/*.rels and [Content_Types].xml.
  • resolve, relative, rels_path and the other part-name functions.
  • PackageOut, RelsOut and ZipOut write a package.
  • check_entry_count refuses an archive that declares too many entries before the zip crate indexes them. Both readers call it.

The limits have no defaults: each format keeps its own numbers.

use ravenrs_sheet::craft::opc::{Limits, Package, PackageOut, RelsOut};

let mut out = PackageOut::default();
out.xml_part("word/document.xml", "application/vnd.openxmlformats-officedocument.wordprocessingml.document.main+xml", b"<w:document/>".to_vec());
let mut rels = RelsOut::default();
rels.add("officeDocument", "word/document.xml", false);
out.rels("", &rels);
let bytes = out.finish()?;

let pkg = Package::open(&bytes, &Limits::new(1000, 1 << 20, 1 << 22))?;
let main = pkg.rels("").first("officeDocument").map(|r| r.target.clone());
assert_eq!(main.as_deref(), Some("word/document.xml"));
assert!(pkg.content_types().of("word/document.xml").is_some_and(|t| t.ends_with("main+xml")));

[Content_Types].xml: Override by part name, then Default by extension (both case-insensitive). The first entry for a name or an extension wins.
LazyPackage
A package whose parts are inflated when they are asked for, against a running total: for a reader that needs a few parts of a large file, or one part at a time.
Limits
What a reader refuses to exceed.
Package
The inflated parts of a package, within Limits. Shared, so a part the caller keeps as it is (a picture, an embedded object) is handed over rather than copied.
PackageOut
A package being written: parts, their content types, and [Content_Types].xml as the first entry.
Rel
One relationship.
RelOut
One relationship being written.
Rels
The relationships of one part, in document order.
RelsOut
The relationships being built for one part. Ids are rId1, rId2… in the order added.
ZipOut
A ZIP archive being written. The output is deterministic: deflate level 6 and the same (1980) timestamp on every entry.
