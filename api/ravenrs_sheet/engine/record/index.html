Module record 

Source
Expand description

The recording buffer: the commands a person (or an agent) ran while recording, each with the document, sheet and selection it ran in.

Only top-level calls are kept. A command that runs other commands (Custom Views › Show, a script) is one step, so playing the recording back does not run the inner commands twice. The buffer is separate from the journal, so trimming the journal never loses recorded steps, and secret parameters are left out as they are in the journal (crate::engine::cmd::journal_params).

Constants§

NOT_RECORDED
Commands never recorded: recovery actions and the debugger, not steps of the person’s work. A recording that replayed Stop Action would stop the run it is a step of, and the debugger runs on its own, never as a step of a script or macro.
RECORD_LIMIT
The most steps one recording keeps; later ones are counted in Recorder::dropped.
RECORD_MAX_BYTES
The most bytes (steps serialized as JSON) one recording keeps. A step keeps its full parameters so it can be played back, and a file.open holds the whole file as base64, so without a size cap a recording of a few opens of a large workbook keeps tens of MB alive.
