Regional formats: how a region writes numbers, dates, times and money.

Excel takes these from the operating system’s regional settings; they are independent of the interface language and of the formula language. A Region changes what people type into a cell (1.234,56, 25/09/2026) and what cells show (separators, month and day names, AM/PM, the system short and long dates). It never changes what is stored: values are numbers, and the number format codes saved in a file stay in their canonical en-US spelling.

EN_US is the default and reproduces GridCraft’s original behaviour exactly.

§Where the values come from

The separators, month and weekday names, AM/PM words, currency symbols and the order of day, month and year are the Unicode CLDR conventions (unicode-org/cldr-json: cldr-numbers-full/main/<locale>/numbers.json and cldr-dates-full/main/<locale>/ca-gregorian.json), which is also what macOS, Android and ICU ship. They were read from those files for en-GB, en-IN, cs and ru, read from ICU’s CLDR 48 data for the Swiss regions and nl-NL, and written from the same conventions for the other regions. CLDR data is under the Unicode License v3, reproduced in NOTICE (row in ATTRIBUTION.md). Deliberate choices where operating systems differ from CLDR:

  • Short dates use a four-digit year (dd/mm/yyyy, where CLDR has dd/MM/y or dd/MM/yy): Excel’s short date is the system’s, Windows writes four digits, and a two-digit year would not read back to the same date.
  • The long date is CLDR’s full date (with the weekday), like Windows en-US, except where Windows’ long date differs: Russian, Japanese and Chinese have no weekday (23 августа 2005 г., 2005年8月23日), as in Microsoft’s National Language Support tables.
  • Korean writes the short date yyyy-mm-dd (CLDR: yy. M. d.), also as in Microsoft’s National Language Support tables.
  • Month names for mmm are CLDR’s abbreviated names (so en-GB has Sept), except Portuguese, which drops CLDR’s period (jan, not jan.) as Excel in Brazil shows it.
  • French and Portuguese (Portugal) group digits with U+00A0 (Windows), not CLDR’s U+202F. Parsing accepts every space-like grouping character in those regions.
  • The Swiss regions (en-CH, de-CH, fr-CH, it-CH; Liechtenstein uses de-CH) group digits with CLDR’s ASCII apostrophe (1'234.50); parsing also accepts the typographic ’ that glibc uses. French (Switzerland) writes a decimal point like the other Swiss regions and glibc’s fr_CH, where CLDR has a comma.

Regions this module doesn’t list (de-AT, es-MX, en-CA…) resolve to the main region of their language through lookup; their own conventions (a Mexican decimal point) are not modelled.

lookup
The region for a tag as operating systems and browsers write it: pt-BR, pt_BR.UTF-8, de, en-AU, zh-Hant, sr_RS@latin. An exact match wins; otherwise the language’s main region (with the usual variants: en-AU→en-GB, pt-AO→pt-PT, zh-Hant→zh-TW). An unknown language is English (United States).
