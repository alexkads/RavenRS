WordCraft geometry and units.

Layout works in points (1/72 inch, f32). File formats use other units: OOXML uses twentieths of a point (twips) for most lengths, half-points for font sizes, eighths of a point for borders and English Metric Units (EMU, 914 400 per inch) for drawings. The conversions live here so every crate agrees on them.

Modules§

picture
Decoding a picture within a memory budget. Every crate that decodes a document’s or the clipboard’s pictures goes through probe (or probe_dib): the header gives the format and size, and the decode is refused before anything is allocated when its peak would pass the budget. The peak counts what a decoder holds beside its output (a progressive JPEG’s coefficients, #3644), and a picture whose decoder can’t be held to a budget is not decoded at all (a TIFF with JPEG strips, #3645).

decode_fits
Whether decoding a w×h picture fits budget bytes at its peak: the decoder’s buffer and the RGBA conversion (or its premultiplied copy) are alive together, so two RGBA buffers. For a decoder whose buffer isn’t four bytes a pixel, see decode_peak_fits.
decode_peak_fits
decode_fits for a decoder that hands back native bytes a pixel (8 for 16-bit RGBA, 16 for float RGBA): its buffer lives alongside the RGBA8 conversion, then the conversion alongside its premultiplied copy, so the peak is the larger of native + 4 and 8 bytes a pixel.
