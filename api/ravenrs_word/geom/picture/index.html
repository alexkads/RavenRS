Module picture 

Source
Expand description

Decoding a picture within a memory budget. Every crate that decodes a document’s or the clipboard’s pictures goes through probe (or probe_dib): the header gives the format and size, and the decode is refused before anything is allocated when its peak would pass the budget. The peak counts what a decoder holds beside its output (a progressive JPEG’s coefficients, #3644), and a picture whose decoder can’t be held to a budget is not decoded at all (a TIFF with JPEG strips, #3645).

background_size
The pixel size of a page-background picture the page raster draws (Design > Page Color > Fill Effects), or None when it leaves the background out: not a raster picture it can read (a metafile is not) or one with no pixels or more than MAX_BACKGROUND_PIXELS. The raster and the strict check both ask this, so they can’t drift.
check_for_drawing
Whether a raster picture decodes for drawing, by the rule the exporters use (probe within crate::geom::MAX_DECODED_BYTES, then decode_for_drawing with max_side).
decode
probe, then Probe::decode within budget bytes.
decode_for_drawing
Decode a raster picture for drawing: the one decision the PDF export, the raster renderer and strict export’s check all take. The decoder is held to max_side pixels a side and the header is charged against budget bytes before anything is allocated. A picture with no pixels or a side past max_side is refused.
probe
Read a picture’s header: PNG, JPEG, GIF, WebP, BMP or TIFF.
probe_dib
Read a DIB’s header: a BMP without its 14-byte file header, as the Windows clipboard holds one (CF_DIB, CF_DIBV5). Its layout is first made the one the decoder reads (see [dib_layout]).
