Expand description

Floating placement (ignored when wrap is Inline).

Fields§

§wrap: Wrap§wrap_text: WrapText

The sides text wraps on (Square, Tight and Through).

§h_rel: Anchor§v_rel: Anchor§x: f32

Offsets, points (used when the matching alignment is None).

§y: f32§h_align: Option<FloatAlign>

Alignments within the anchor area; they take precedence over the offsets.

§v_align: Option<FloatAlign>§dist: f32

Distance from surrounding text at the left and right (points).

§dist_top: f32

Distance from surrounding text above and below (points).

§dist_bottom: f32§effect: [f32; 4]

Room around the object for effects such as shadows (left, top, right, bottom, points), inline or floating: lines and surrounding text keep clear of it. Rotation’s own overhang is not in here: it follows from Float::rot (see Float::spin_pad).

§rot: f32

Rotation clockwise about the object’s centre, degrees (DrawingML a:xfrm/@rot). Offsets and the size stay those of the unrotated frame, as in Word; see Float::spin.

§flip_h: bool

Mirrored left to right / top to bottom (a:xfrm/@flipH, @flipV).

§flip_v: bool§wrap_polygon: Option<Arc<WrapPolygon>>

The outline Tight and Through wrapping follow (wp:wrapPolygon), in the object’s own (unrotated) frame; None = derived from the object (see crate::doc::wrap).

§alt: AltText

What the drawing is, for screen readers and exports (wp:docPr @descr, @title and the decorative mark). See InlineObject::alt_text.

§hidden: bool

Hidden (wp:docPr/@hidden, VML visibility:hidden): kept and saved, but neither drawn nor laid out, as Word for Windows does (Word for Mac draws hidden VML shapes).

§outside_cell: bool

Anchored in a table cell but placed on the page, not in the cell (wp:anchor/@layoutInCell off, any VML shape in a header or footer): a picture watermark in a header that starts with a table.

§z: u32

Stacking order among floating objects (wp:anchor/@relativeHeight): higher is drawn on top. 0 = unknown, drawn in document order (objects inserted here, or from other formats).

§page: u32

The page a drawing anchored to a page is on, from 1 (ODF’s text:anchor-page-number, §19.872); 0 = anchored to its paragraph or not said. Kept for saving: the layout places a drawing on its anchor paragraph’s page.

§bare_turn: bool

Turned, but the file keeps no room for the turn (wp:effectExtent missing or zero, as files from other tools have): Word then keeps an inline one’s line to its frame and lets the turned object overhang it (see Float::line_pad). Cleared by Float::set_spin.

The rotation and flips, the angle normalised to 0..360 (a NaN angle is no rotation).

Set the rotation and flips (the angle normalised).

Source

pub fn spin_pad(&self, w: f32, h: f32) -> (f32, f32)

How far a w × h frame’s rotated bounds reach past it on each side (x, y): the room a rotated object takes beyond its frame (zero unrotated; negative where the turned object is narrower than its frame, as a wide picture turned 90° is).

Source

pub fn is_bare_turn(&self) -> bool

A Float::bare_turn still inline and without effects room: made floating, or given room for a shadow or glow since, it saves, and so lays out, with the turn’s room again.

Source

pub fn line_pad(&self, w: f32, h: f32, modern: bool) -> (f32, f32)

The room an inline w × h object’s line keeps past its frame on each side (x, y) for its turn: its rotated bounds (Float::spin_pad) — or, for a Float::is_bare_turn, none, except that Word 2013+ layout (modern) exchanges the frame’s width and height from 45° up to 135° and from 225° up to 315°.

Source

pub fn effect_extent(&self) -> [f32; 4]

The effect extents, finite and clamped (left, top, right, bottom).
