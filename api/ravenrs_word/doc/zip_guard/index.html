Module zip_guard 

Source
Expand description

A bytes-only check of a ZIP package’s declared entry count before the zip crate opens it (#3660). Every reader of .docx, .odt and spreadsheet packages calls check first.

zip::ZipArchive::new reserves room for, and parses, as many central directory headers as the end record declares before its caller can look at len(). A ZIP64 end record can declare millions of entries for a file of a few hundred megabytes (only 46 bytes each have to fit), and each parsed entry costs several times that in memory. Here the end records are found the way zip finds them (APPNOTE.TXT §4.3.14 to §4.3.16), and a package declaring more than the reader’s limit is refused before zip parses anything. Anything else that is wrong is left for zip to report.

Functions§

check
Refuse bytes when the end record zip would use declares more than max_entries entries.
