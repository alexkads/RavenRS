pub fn check(bytes: &[u8]) -> Result<(), String>
Expand description

Check a compound file’s FAT layout before cfb reads it ([MS-CFB] §2.2 header, §2.5 DIFAT). cfb appends a whole sector of FAT entries for every FAT sector the DIFAT lists and only validates the FAT once it is built, so a small header naming one sector over and over makes it allocate gigabytes. Here the DIFAT is walked the way cfb walks it (header entries, then the DIFAT chain, at most one step per sector; trailing zero and free entries trimmed the same way) and the file is refused when it lists one FAT sector twice, or more FAT sectors than the file has sectors — every FAT sector is a sector of the file, so a longer list is duplicates or names cfb refuses anyway, and the FAT cfb builds (one sector of entries per listed name) stays within about the file’s own size. Anything else that is wrong is left for cfb to report.
