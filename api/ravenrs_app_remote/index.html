Crate ravenrs_app_remote 

Source
Expand description

An application over the web API of ravenrs-app-server, on the desktop and in the browser.

The screens read and write through an ObjectSpace, which answers at once, and a browser cannot wait for the network. So RemoteDatabase keeps a copy in memory of what the person can see, screens work over that copy, and a commit goes to the server as one batch.

A transport that answers before returning, as the one on the desktop does, makes a commit wait for the server, and what it refuses is refused there and then. One that answers later, as in a browser, keeps what was done in the copy at once and sets it right when the answer comes: what the server refused goes away, and whoever watches is told with on_problem.

The server decides everything. The copy only ever holds what the person can see, so nothing here is a permission, and being taken apart gives nobody anything more.
