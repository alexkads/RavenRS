Runs end-to-end scenarios of RavenRS apps and reports them: the engine shared by Raven Test Studio (RTS) and cargo ravenrs e2e.

  • project reads a Rust project without building it: its RavenRS packages, which are apps, whether each speaks the test channel (ravenrs-e2e-wire), its .raventest scenarios and the screens it builds.
  • app opens an app apart, in a child process with no window: its code compiled by build, a copy the installer put on the computer, or a binary a variable names.
  • session is what a run drives and how each step goes: the step a block stands for, and why it failed, by its stable code, with the meaning and the fix in Portuguese.
  • window runs with the app’s real window on screen (--headed): the pace a person can follow, pause, one more block, stop, and the window kept open to look at a failure.
  • run runs .raventest files straight from their blocks, and report says how it went as text, JSON, JSON lines or JUnit, and keeps it in a folder (relatorio.json, trace.jsonl, arvore.txt).
use ravenrs_e2e_runner::{app, project, run};

let project = project::read(std::path::Path::new(".")).unwrap();
project.learn_apps();
for folder in project.scenario_folders() {
    let report = run::run_files(&folder, app::open).unwrap();
    println!("{}", report.text());
}

Modules§

app
The apps a scenario opens apart, in a child process with no window, over the test channel.
build
Compiles an app before it opens its test channel. This layer reads Cargo’s JSON output and uses the shared process executor for the deadline and process-group cleanup; it does not know the Studio, installed apps or how a project is discovered.
config
e2e.toml: the choices of an app’s suite, kept next to its Cargo.toml (T11 of #627).
driver
Driver: the one way a run drives an app, block by block, for every tool that runs scenarios: cargo ravenrs e2e, which runs files straight from their blocks, and Raven Test Studio, which runs the blocks of its diagram one at a time. It opens the app a block names, runs each step, times it, asks for the screen when it fails, and films the app when asked (6.4 of #627).
html
The report of a suite as one HTML page (T5 of #627): the summary, a table per scenario with each block, and the failure with its meaning, fix and the app’s screen. The page needs nothing from the network, reads in light and dark, and fits a phone.
project
A Rust project the Studio is pointed at: which of its packages are made with RavenRS, which of them are apps, whether each speaks the test channel, which scenarios it keeps, and which screens it builds, so a person knows what can be tested there without knowing the project.
report
What a run tells whoever asked for it: a person in a terminal, a build server, or the coding agent that called the tool.
run
Running .raventest files straight from their blocks, with no diagram: what cargo ravenrs e2e run does, and anything else that runs scenarios without a window.
rust
A scenario as a Rust integration test (T6 of #627), to read, or to keep in an app’s tests/ when a team prefers Rust: it opens the app’s binary with --e2e-serve and sends one command of the test channel per block, as cargo ravenrs e2e run does.
session
What a run drives and how each step goes: the app under test (in this process or apart, over the test channel), the step a block stands for, why a step failed in words a person reads (Portuguese, by the stable code) and how each block went.
window
Running with the app’s real window on screen (--headed, #729): the mode, the pace a person can follow and the window kept open to look at a failure.
