pdfcraft-fonts — font metrics and encodings for generated appearances (L2).

Standard-14 advance widths are exact (Std14, ISO 32000-2 Annex D). What remains approximate is everything that needs a font program: this crate reads font dictionaries, never embedded programs, so it has no glyph outlines for document fonts and cannot subset or re-embed. That is phase F 4.2 in docs/plan/execution-plan.md.

Modules§

embedding
Unicode embedding of an explicitly supplied, embeddable TrueType face. Font files are document inputs or the optional craft-fonts build input, never system-interface fallbacks.
fallback
The one chain PdfCraft follows when a document does not embed a font program, and a record of what it chose and why.
pdf
What content editing and redaction need from a PDF font: how to split a string into character codes, each code’s advance width, the glyph height (ascent, descent), and what each code means (Unicode) — and back, which text the font can show. Widths come from the font dictionary (/Widths, /W, /DW, /MissingWidth); a simple font with no /Widths uses its embedded sfnt program’s advances, else the exact published standard-14 metrics (crate::fonts::Std14).
plan
Planning visible Unicode text output for OCR: which characters the standard WinAnsi fonts show as is, which need a Type3 font drawn from the craft-fonts faces, and which have no glyph anywhere (written as ? — and counted, never silently dropped).
shaped_text
Shaped text written into a PDF: each distinct shaped cluster (a letter with its marks, and the text it stands for) becomes one glyph of a Type 3 font drawn from the craft-fonts face’s outlines, with a /ToUnicode map so copy and search get each character once. No font file is embedded. Add text writes Arabic, Hebrew and Thai with it; text boxes, Fill & Sign text, form fields, headers, footers and watermarks write Thai with it, beside the standard font that draws the rest (thai_pieces).
source_shaping
Shaping an explicitly selected source/document face, with OpenType features and UAX #9.

UNDRAWN_MARK
The private key on an annotation (a comment or a form field’s widget) whose appearance PdfCraft drew with ? in place of characters its fonts can’t draw: a text string holding the first such character. The text itself (a field’s /V, a comment’s /Contents) is stored as typed; the mark lets flattening refuse to make that ? permanent, lets an edit report it, and tells such an appearance apart from one another program drew with a font that has those characters.
