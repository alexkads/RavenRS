pdfcraft-render — page rasterization and document inspection.

Bootstrap status (see ADR-0004): rasterization goes straight through the hayro crate (hayro-interpret + vello_cpu). Inspection uses the lazy cos reader with a read-only lopdf object adapter and retains lopdf loading for compatibility repairs. The renderer and that adapter are replaced by model and the DisplayList design in M1–M2. The public API is what the engine and UI rely on, so the swap stays internal to this crate.

Functions§

attachment_data
Fetch an attachment’s bytes (decoded). Capped at 1 GiB to defuse decompression bombs. A document opened without the password its embedded files need (/AuthEvent /EFOpen, ISO 32000-2 §7.6.6) holds them encrypted: asking for one is an error, never its encrypted bytes.
check_pages
Check that bytes still open as the same document: the parser reads them and the page count matches. Content-only edits skip the full inspect (seconds on very large files) but must still catch an edit that produced something the viewer cannot display, so the caller can roll it back. Never panics: parser crashes are caught and reported.
device_pixels
Device pixels that cover pt points at scale: rounded up, as poppler’s pdftoppm does, so the last partial row or column of a page is drawn (anti-aliased against the background) rather than cut off. Float noise up to 1/100 px is not rounded up, so 612 pt at 150 dpi stays 1275 px. At least 1; saturates instead of overflowing.
effective_scale
Clamp a requested scale so the output respects MAX_SIDE and MAX_PIXELS.
fill_group_text
Give a group’s StrikeOut primary with no text of its own (/Contents missing or empty) the text of its first Caret subordinate that has some. A reader ignores a subordinate’s /Contents (ISO 32000-2 §12.5.6.2), but Replace Text groups written by earlier PdfCraft builds made the strikeout the primary, with no text, and kept the replacement only on the caret: without this they would list as a comment with no text. A primary’s own text always wins, no other subordinate lends its text, and no other kind of primary borrows one. Only the listing changes, not the file.
group_primaries
For each annotation of all, the position in all of the primary of the group it is a subordinate of (Annotation::is_group_member, ISO 32000-2 §12.5.6.2), or None when it is not one. The group’s attributes, its comment and its replies are the primary’s. A subordinate of a subordinate leads to the first non-subordinate up the /IRT chain. Expects links link_replies settled: a subordinate whose chain loops or names nothing listed has lost its parent there and is a comment of its own, as such a reply is. One still on a subordinate after MAX_GROUP_DEPTH steps has no primary (None) and is listed under no comment.
inspect
Inspect a document. Fails only if the renderer itself cannot open the file (or needs a password). Never panics: parser crashes are caught and reported.
link_quads
A link’s quadrilaterals from its /QuadPoints values (None for an entry that isn’t a number), or an empty list when the link is active over its whole /Rect: no values, a count that isn’t a multiple of 8, more than MAX_LINK_QUADS, a value that isn’t a finite number, a corner outside rect (normalized, [x0, y0, x1, y1]), or no quadrilateral that encloses an area.
link_replies
Settle the reply links of a document’s annotations: a reply keeps its parent only when following the links reaches a comment of its own. An /IRT to an unlisted object, a pop-up, the annotation itself or a loop leaves it a comment of its own, so it stays in view instead of hanging off nothing. A chain of any length settles: each reviewer’s state changes reply to their previous one (ISO 32000-2 §12.5.6.3), so a long review history is a long chain. Each annotation is walked once, with a seen-set against loops. Both comment readers (inspect, and the engine’s list after an edit) run this.
named_destination
The (0-based page, view) of the named destination name (ISO 32000-2 §12.3.2.4): a key of the /Names /Dests name tree or of the PDF 1.1 catalog /Dests dictionary, as a link’s or /OpenAction’s name resolves. None when the document can’t be read, has no such name, or the name leads to no page of it. A key matches name written in UTF-8 or in PDFDocEncoding, or as a text string (UTF-16 or PDFDocEncoding) that reads as name, the way a link’s string destination is read. Read like inspect: the lazy reader first, lopdf’s tolerant one when the lazy reader fails.
pretty_date
D:20260930104512-04'00' → 2026-09-30 10:45. A PDF date (D:20261001123000Z) as “2026-10-01 12:30”; other strings unchanged.
quad_contains
Whether the point (x, y) lies in the quadrilateral q (x1 y1 … x4 y4), edges included. Writers disagree on the corners’ order (the specification says counterclockwise, text-markup writers often go top-left, top-right, bottom-left, bottom-right), so the quadrilateral is taken as the area its four corners enclose: the union of the four triangles they make.
resolve_uri
The address a URI action goes to when the document’s catalog gives base (/URI /Base): a relative reference (page.html, ../a/, ?q=1, //host/x) resolved against it by RFC 3986 §5 (the WHATWG URL rules, which the browser applies too). None when the address is used as written: it already has a scheme (https:, mailto:, javascript:…), there is no usable base, or the result wouldn’t be a web address.
thread_tops
The comment each reply’s thread starts from, by the reply’s page and /Annots position: a reply to a reply files under that comment too. Expects links link_replies settled; a loop in an unsettled list ends where it comes back round.
