PDF stream filters (ISO 32000-2 §7.4).

Layer L0, standalone: this crate depends on no other PdfCraft crate.

Decoding covers the general-purpose filters (FlateDecode, LZWDecode with TIFF/PNG predictors, ASCIIHexDecode, ASCII85Decode, RunLengthDecode). Image codecs (DCTDecode, JPXDecode, JBIG2Decode, CCITTFaxDecode), Crypt and unknown filters are reported as FilterError::Unsupported so callers keep such data encoded. CCITT fax and JBIG2 images decode on their own (decode_ccitt_within, decode_jbig2_within), each spending from an allowance its caller shares across a run of images, as crate::cos::ImageBudget::decode does after the filters before them. Neither decodes without one:

ⓘ
let _ = ravenrs_pdf::filters::decode_jbig2(&[], None, 1, 1, 1 << 20);
ⓘ
let _ = ravenrs_pdf::filters::decode_ccitt(&[], &ravenrs_pdf::filters::CcittParams::default(), 1);
let mut work = 1 << 20;
assert!(ravenrs_pdf::filters::decode_jbig2_within(&[], None, 1, 1, 1 << 20, &mut work).is_err());
let p = ravenrs_pdf::filters::CcittParams { columns: 8, ..Default::default() };
assert!(ravenrs_pdf::filters::decode_ccitt_within(&[], &p, 1, &mut work).is_ok());

1-bit samples can be encoded as CCITT Group 4 (encode_g4) or lossless JBIG2 (encode_jbig2), a group of images sharing their marks through /JBIG2Globals (encode_jbig2_shared).

Every decoder is bounded by a caller-supplied max_output (decompression-bomb defence) and never panics on malformed input.

Constants§

FLATE_READ_WORK
The steps each byte Flate reads costs where decoding is paid for (decode_tolerant_within, decode_within), besides the step it was paid as input and a step for each byte it makes. Inflating does work for every block it reads, whether or not the block makes anything: an empty fixed-Huffman block is ten bits (RFC 1951 §3.2.6). With flate2’s zlib-rs backend (zlib-rs 0.6.8, release build) the slowest blocks measured, empty dynamic ones, took 21 ns a byte read to make nothing, empty fixed ones 9 and fixed ones of a literal each 6, so at this price the worst per byte read comes to about 7 ns a step, inside what a step of JBIG2 decoding takes. (miniz_oxide 0.9.1, flate2’s backend here before, took about 1.7 µs for every fixed-Huffman block, empty or not: 1,383 ns a byte read on empty ones.) A stage’s start isn’t priced, about 0.25 µs: every way to repeat one takes bytes of the file, so what starts cost is bounded by the file’s length. Data a real encoder makes took 0.2 to 2.3 ns a byte made, its reading included, so an image pays twice its stored length more than it would unpriced.
MAX_CCITT_COLUMNS
The widest row decode_ccitt_within decodes: its row buffer stays within 128 KiB.
MAX_CHAIN
Longest filter chain decoded. Real streams use one to three filters; every stage may produce up to the output limit, so the chain length multiplies the work.
MAX_G4_COLUMNS
The widest row encode_g4 encodes. The encoder counts the positions in a row in 16 bits and adds two of them, so a row stays within half that range.
MAX_JBIG2_COLUMNS
The widest row, and the most rows, encode_jbig2_generic encodes: what hayro-jbig2, the decoder behind JBIG2Decode here, takes on a side. JBIG2 allows 32-bit sizes, but past this nothing here could read the stream, and the optimizer, which doesn’t read back what it stores, replaced such an image with one that draws nothing.
MAX_JBIG2_PIXELS
The largest JBIG2 page decode_jbig2_within decodes, in pixels. The decoder decodes a page whole, and takes pages of up to this many (20,000 × 10,000 decodes). It is also the most encode_jbig2_generic encodes, so what it stores reads back.

decode
Decodes data through chain (first element applied first).
decode_ccitt_within
CCITT fax data decoded as CCITTFaxDecode gives it: rows of columns 1-bit samples, most significant bit first, each starting on a new byte, with black as 0 (as 1 with black_is_1).
decode_counted
Like decode for a caller charging an allowance: max_output bounds the bytes all stages decode together, each stage getting what the earlier ones left, and the result gives those bytes, on success and on failure. A stage’s output counts even when a later stage or its predictor shrinks it.
decode_image_tolerant_within
decode_tolerant_within for the samples of an image rows high (its /Height), which the last stage gives. When that stage is Flate with a PNG predictor and gives exactly rows rows without the filter-type byte each predicted row starts with (ISO 32000-2 §7.4.4.4), its writer declared the predictor without applying it: the output is taken as the samples, as other readers take it, and reported as the damage it is, like any other corruption tolerated here. Any other output has its predictor undone as decode_tolerant_within does.
decode_jbig2_within
A JBIG2Decode stream’s data, with what its /JBIG2Globals stream decodes to, decoded as the filter gives it: rows rows of columns 1-bit samples, most significant bit first, each starting on a new byte, with black as 0 (JBIG2 codes black as 1).
decode_tolerant
Like decode, but on corrupt data returns what was decoded before the error and reports partial = true (the behaviour viewers expect). The remaining filters of the chain still run on the partial data. Limit and unsupported errors are still errors.
decode_tolerant_counted
decode_tolerant bounded and counted as decode_counted is.
decode_tolerant_counted_each
decode_tolerant_counted with the two bounds apart: max_stage bounds every stage, as decode_tolerant’s bound does, and max_output the bytes all stages decode together. A stage stopped by either gives FilterError::LimitExceeded and the bytes decoded before it.
decode_tolerant_within
decode_tolerant, spending from work, what decoding may still cost across a run of images: a step for each byte of data, paid before anything is decoded, FLATE_READ_WORK for each byte a Flate stage reads, paid before it runs (again if it reads them twice), and one for each byte a stage decodes, so a chain that fails, or a stage that goes past max_output, has paid for what it did. No stage decodes past what is left: a chain that work can’t pay for spends all of it and stops there, so with nothing left nothing is read. A chain that can’t be decoded at all costs nothing, whatever is left, so what an image’s filters are is known from the error.
decode_within
decode, spending from work as decode_tolerant_within does: corrupt data is an error, having paid for what was decoded before it.
encode
Encodes data with filter. Supported: Flate (zlib, level 6), LZW, ASCIIHex, ASCII85, RunLength. For Flate and LZW, params.predictor >= 2 applies the predictor first (TIFF 2, PNG 10–15; 15 chooses the per-row optimum).
encode_flate
zlib (RFC 1950) at compression level 6.
encode_g4
rows rows of columns 1-bit samples, most significant bit first, each row starting on a new byte (as a PDF image’s samples are packed), encoded as CCITT Group 4 with an end-of-block mark.
encode_jbig2
rows rows of columns 1-bit PDF samples as lossless JBIG2, the smaller of two codings: encode_jbig2_generic’s, or one that stores each distinct mark of the image once, as a symbol, and places its copies (see [symbols]). Either way the stream is in the embedded organisation and decodes to the same bits without /JBIG2Globals.
encode_jbig2_generic
rows rows of columns 1-bit PDF samples (most significant bit first, each row starting on a new byte), as a JBIG2 stream in the embedded organisation: a page information segment and an immediate lossless generic region segment, which JBIG2Decode decodes to the same bits without /JBIG2Globals.
encode_jbig2_shared
Images, each rows rows of columns 1-bit PDF samples, as lossless JBIG2 sharing one symbol dictionary: the marks found in more than one of them are stored once, in a symbol dictionary segment not associated with a page, which is the /JBIG2Globals stream’s data, and each image’s stream, in the embedded organisation, places them from there, with its other marks coded as encode_jbig2’s symbol coding codes them (see [symbols]). With the globals, each decodes to its own bits. An image that holds none of those marks, or that symbol coding doesn’t take, has no stream here; it is stored alone. None when the images share fewer than two marks.
