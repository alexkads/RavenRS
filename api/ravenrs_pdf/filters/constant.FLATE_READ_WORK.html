The steps each byte Flate reads costs where decoding is paid for (decode_tolerant_within, decode_within), besides the step it was paid as input and a step for each byte it makes. Inflating does work for every block it reads, whether or not the block makes anything: an empty fixed-Huffman block is ten bits (RFC 1951 §3.2.6). With flate2’s zlib-rs backend (zlib-rs 0.6.8, release build) the slowest blocks measured, empty dynamic ones, took 21 ns a byte read to make nothing, empty fixed ones 9 and fixed ones of a literal each 6, so at this price the worst per byte read comes to about 7 ns a step, inside what a step of JBIG2 decoding takes. (miniz_oxide 0.9.1, flate2’s backend here before, took about 1.7 µs for every fixed-Huffman block, empty or not: 1,383 ns a byte read on empty ones.) A stage’s start isn’t priced, about 0.25 µs: every way to repeat one takes bytes of the file, so what starts cost is bounded by the file’s length. Data a real encoder makes took 0.2 to 2.3 ns a byte made, its reading included, so an image pays twice its stored length more than it would unpriced.
