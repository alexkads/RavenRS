Struct DecodeBudget 

Source 
pub struct DecodeBudget { /* private fields */ }
Expand description

What one operation may still decode and enter across all the streams it reads.

MAX_DECODED bounds one decode. It does not bound a page whose /Contents names the same compressed stream thousands of times, or a form drawn thousands of times from other forms: each occurrence would get a fresh allowance. A DecodeBudget is shared by every decode of one operation, so the total decoded bytes and form entries stay under fixed limits however the file repeats its references. A decode that runs past the remaining allowance spends all of it, so a bomb referenced many times is inflated once.

pub fn decode_within( &mut self, stream: &Stream, max: usize, ) -> Result<Vec<u8>, CosError>

Like DecodeBudget::decode, for a stream with a tighter bound of its own: decoding past max bytes is an error that charges max, the work it took to find out.

Source

pub fn decode_stages_within( &mut self, doc: &Document, stream: &Stream, max: usize, ) -> Result<Vec<u8>, CosError>

Like DecodeBudget::decode_within, with every filter stage held to max, as Stream::decoded_within holds it, and the stages together to max for each of them, the stream’s /DecodeParms given by reference read in doc through a view of it that shares its data and copies no more of its dictionary than its filters and parameters (DecodeBudget::decode_with_damage reads it so). A stream so reads here when it reads without an allowance and the allowance can pay for what its stages decode, the output of one stage on top of another’s. A stage past max is an error that charges what the stages before it decoded and max, the work it took to find out; past the stages’ total it charges that total, and past what is left it spends all of it, as DecodeBudget::decode_within does.

Source

pub fn decode_with_damage( &mut self, doc: &Document, stream: &Stream, max: usize, ) -> Result<(Vec<u8>, bool), CosError>

DecodeBudget::decode_within (usize::MAX for no bound of its own), with the stream’s /DecodeParms given by reference read in doc, also saying whether the stream is damaged: true when a filter stopped at corrupt data, so the bytes are only what decoded before it. A stream written back from them loses everything after the damage, which other readers may still read.

stream decoded like Stream::decoded_strict (any corruption is an error), charged to the allowance, with its /DecodeParms given by reference read in doc.

pub fn decode_contents( &mut self, doc: &Document, contents: &Object, ) -> Vec<Result<Vec<u8>, CosError>>

Each stream contents names, decoded against the allowance, in order, its /DecodeParms given by reference read in doc. contents is a page’s /Contents: one stream, or an array whose non-stream entries are left out. A stream that fails to decode, or arrives after the allowance is spent, is an Err in its place, so the caller chooses between skipping it and giving up.
