pub fn reconstructed(&self) -> bool

There is no cross-reference chain to append to: the index was rebuilt from object headers because the file’s own was unusable (see Self::repair_log), or the document was built from scratch (Self::new_empty). A save writes such a document in full, even when nothing was edited: for a repaired file that is what puts the repair on disk.

pub fn revision_ends(&self) -> Vec<usize>

Where each revision of the file ends (oldest first): the byte after the %%EOF (and its end-of-line) that closes its cross-reference section. data[..end] is that revision as it was saved. A linearized file’s first-page section belongs to the revision it precedes, so ends only ever increase. Empty for a reconstructed file.

pub fn rebuilt_unlinked_update(&self) -> bool

Whether the file was rebuilt from its object headers because its last update has no /Prev and so cut its page tree off the cross-reference chain (ISO 32000-2 §7.5.6, §7.5.8.2). The renderer rebuilds such a file under the same conditions, so the two read the same objects.

pub fn unreadable_objects(&self) -> Vec<String>

Objects of the file that could not be read, lowest number first, as lines such as “object 11 0 could not be read: syntax error at byte 512: …”. Self::get reads each as null (ISO 32000-2 §7.3.10), so a document with one opens, but what it held is lost: unlike Self::repair_log, nothing was repaired. Lists the objects read so far, by this document, its clones or a scan of it, that have not since been edited; past 100, a last line says there were more. Opening again, authenticating or rebuilding the index starts the list afresh, as it does the object cache.

pub fn xref_oddities(&self) -> &[(u64, u32)]

Cross-reference entries this reader did not take at face value, as (byte offset of the section, object number): an in-use entry at offset 0, a second and different entry for one object in the same section, a reserved cross-reference stream entry type, or a hybrid /XRefStm entry that disagrees with the table. The reader sets such an entry aside and keeps what it already had for the object. Another reader, the page renderer among them, may follow it instead, so the two can then show different objects for one number. Code that compares revisions (signature validation) must not call such an object unchanged.

pub fn xref_entry_is_exact(&self, num: u32) -> bool

Whether the cross-reference entry of num locates that object itself: its num G obj header at exactly the recorded offset, or the member with that number at the recorded position of its object stream. When it does not, Self::get still finds the object by searching, but another reader may resolve the number differently. Ignores unsaved edits.

pub fn get(&self, r: ObjRef) -> Arc<Object> ⓘ

Fetch an object by reference. Undefined references are Null (ISO 32000-2 §7.3.10). A live file slot also accepts its actual header generation when a damaged xref row disagrees; the disagreement is recorded in Self::repair_log. Free slots never do.

Source

pub fn accepted_generations(&self, num: u32) -> Vec<u16>

The generations a reference to num may carry and still resolve (see Self::get), sorted: none for a free or unknown slot, else the slot’s generation, and for a damaged file slot (or a repair-aware edit of one) also the generation its object header carries. Code comparing revisions (signature validation) uses it to tell whether the references that reached an object in one revision still reach the same slot in another.

pub fn resolve(&self, o: &Object) -> Arc<Object> ⓘ

Follow a reference if o is one; otherwise return o itself. An object can be nothing but a reference to another, which is followed too, up to [MAX_REFERENCE_HOPS] of them.

Source

pub fn with_direct_parms<'s>(&self, s: &'s Stream) -> Cow<'s, Stream>

s with the /DecodeParms its filters use made direct, so Stream::decoded reads them: an indirect dictionary resolved, and of an array (itself perhaps indirect), the entries at the filters’ places (/Crypt counts, ISO 32000-2 §7.4.1) resolved, the rest dropped. Of each dictionary only the entries the decoders read are kept, numbers and flags given by reference (/Predictor 7 0 R) resolved; /JBIG2Globals stays a reference. A /Crypt entry, which no decoder reads (Stream::filters leaves it out), is null. s itself when none of those is indirect, or when the other filters are more than any decoder takes (crate::filters::MAX_CHAIN). Only small values are copied, so a file can’t have a large object copied once for each key and filter.

pub fn scan_objects( &self, ) -> impl Iterator<Item = (ObjRef, Arc<Object>)> + use<>

Visit every current object without filling this document’s editing cache.

Full-document searches (for example, standalone timestamps) need to inspect objects that may never be used again. Keep their parse caches private and release them in batches. Returned objects own their data and remain valid after the next batch.

pub fn overlay_changes_from( &mut self, current: &Document, ) -> Result<(), CosError>

Record current’s object graph as unsaved edits of this document.

Used when the working snapshot was restored from an earlier revision and the next incremental save must still append to this file (the last saved revision). Objects that already match are left untouched, except members of an object stream of this file whose stream number current frees or reuses: those are written again on their own. Reads go through private readers so neither document’s editing cache is filled.

pub fn open_with_password( data: Arc<Vec<u8>>, password: Option<&str>, ) -> Result<Self, CosError>

Parse a document, authenticating encrypted ones with password (owner or user; None tries the empty password). Fails with NeedsPassword / WrongPassword as appropriate.

Source

pub fn open_with_stream_limit( data: Arc<Vec<u8>>, password: Option<&str>, stream_limit: usize, ) -> Result<Self, CosError>

Open with a tighter decompression bound for object and cross-reference streams. Inspection can use this without changing the editing reader’s default limit. Such a document is read-only: objects in a larger object stream read as missing, so the writers refuse to save it (CosError::ReadOnlyLimit).

Source

pub fn open_with_same_credentials( &self, data: Arc<Vec<u8>>, ) -> Result<Self, CosError>

Open data, an earlier revision of this file (the bytes a signature covers) or another save of it, with this document’s credentials: an encrypted one must have the same /Encrypt dictionary and /ID as this document, whose file key is then reused, so no password is needed or kept; unencrypted data opens as open does. Data encrypted differently fails with NeedsPassword.

Source

pub fn embedded_files_locked(&self) -> bool

Whether the document opened without the password its embedded files need (/AuthEvent /EFOpen): their data is held, and saved, as stored, and isn’t to be read as the files.

Source

pub fn reads_as_stored(&self, s: &Stream) -> bool

Whether s, a stream of this document, holds encrypted data that reads as stored because the document opened without the password its embedded files need (see Document::embedded_files_locked). Such data isn’t the file it encrypts.

Source

pub fn unlock(&mut self, password: &str) -> Result<(), CosError>

Lift the restrictions of a document opened with its user password by entering the owner (permissions) password (§7.6.4). Fails with WrongPassword for any other password. Does nothing when the document is unencrypted or already opened as owner. Both passwords unlock the same file key, so nothing read so far is decoded again.

The security handler, when the document is encrypted.

pub fn permissions(&self) -> Option<Permissions>

What the opening password allows (None for unencrypted documents: everything).

Source

pub fn require_full_save(&mut self)

Make the next save a full rewrite: earlier revisions (which still hold what an edit removed) must not stay in the file. Redaction requires this.

Source

pub fn require_full_save_with_new_id(&mut self)

Like Document::require_full_save, and the rewritten file also gets a new file identifier (/ID), so that a redacted or sanitized copy never claims to be its source (ISO 32000-2 §14.4). An encrypted file keeps the first string of its identifier, which its key depends on.

Source

pub fn full_save_required(&self) -> bool

The next save must rewrite the whole file (see Document::require_full_save). Repair-aware edits retaining two accepted generations cannot use one incremental slot.

Source

pub fn new_id_required(&self) -> bool

The next full save gives the file a new identifier (see Document::require_full_save_with_new_id).

Source

pub fn encryption_changed(&self) -> bool

Security was set or removed since the document was opened (the next save applies it).

Source

pub fn output_handler(&self) -> Option<&SecurityHandler>

The security the next save writes: protection applied with set_encryption, none after remove_encryption, otherwise the security the document was opened with.

Source

pub fn set_encryption( &mut self, params: &NewEncryption<'_>, ) -> Result<(), CosError>

Protect the document with a password (§7.6.4). Takes effect on the next save, which is always a full rewrite. Returns the handler (authenticated as owner).

Source

pub fn remove_encryption(&mut self)

Remove password protection (requires the document to be open — any authenticated password; callers should require the owner password, §7.6.4). Applied by a full save.
