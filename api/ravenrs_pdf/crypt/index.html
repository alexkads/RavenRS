pdfcraft-crypt — the PDF standard security handler (ISO 32000-2 §7.6), standalone (L0).

Supports every revision of the standard handler:

  • R2 (40-bit RC4), R3 (RC4 up to 128-bit), R4 (crypt filters: RC4 or AES-128);
  • R5 (the deprecated AES-256 extension) and R6 (AES-256, PDF 2.0).

It authenticates with the user or owner password (owner first, as viewers do) and derives per-object keys. It decrypts and encrypts strings and streams, and honours crypt filters, including Identity and embedded-file-only encryption. It can also create encryption dictionaries, which security settings (M8) and our own test fixtures use.

The crate knows nothing about the COS object model. Callers pass in the values of the /Encrypt dictionary and the first element of the trailer /ID.

effective_password
The bytes new encryption with algorithm derives its keys from for password: for R2–R4 its PDFDocEncoding cut or padded to exactly 32 bytes (Algorithm 2); for R6 its SASLprep (the password as given if SASLprep refuses it), at most 127 bytes of UTF-8. Two passwords with the same bytes are the same password to the file, and a password with the bytes of "" opens it without asking, so callers can refuse either before encrypting. Different bytes can still give the same key (RC4-40 keeps 5 bytes of a hash). create still uses the user password for an empty R2–R4 owner password.
