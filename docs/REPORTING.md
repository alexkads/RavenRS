# RavenRS Reporting — design and roadmap

> Status: proposed, 2026-11-01. Reference product: [DevExpress Reporting](https://www.devexpress.com/subscriptions/reporting/).

RavenRS Reporting turns data into paginated documents. It covers what the DevExpress Reporting subscription covers: a report engine, a document viewer, exports, an end-user report designer and a report server. Everything is in Rust and runs on desktop, in the browser (WebAssembly) and on servers.

## Goals

* **One engine everywhere.** The same report definition renders identically in the desktop viewer, the browser viewer, a PDF on a server and a test.
* **Reports are data.** A report is a JSON document (`*.rvreport.json`) that can be designed visually, stored in a database, versioned in git and generated by code or AI.
* **Pixel-exact output.** Layout is computed once into a `Document` of positioned primitives in points. Every exporter and the viewer draw that same document.
* **Commercial depth.** The bands, expressions, summaries, master-detail and controls a business report needs (invoices, statements, labels, ledgers, dashboards), with tests and performance budgets like the rest of RavenRS.

## Architecture

```
            report definition (JSON or Rust builder)      data (JSON, Rust structs, SQL, CSV/XLSX)
                              │                                   │
                              ▼                                   ▼
  ravenrs-report ──── expressions ── data binding ── grouping/sorting/summaries
        │
        ▼  pagination (Parley text measurement, keep-together, page breaks, can-grow/shrink)
   Document (pages of positioned text, rects, lines, paths, images, links; in points)
        │
        ├── ravenrs-report-pdf     PDF 1.7 / PDF/A-2b, embedded font subsets, links, outline (pdf-writer + subsetter)
        ├── ravenrs-report-xlsx    XLSX (rust_xlsxwriter), CSV, HTML, SVG/PNG
        ├── DocumentViewer widget  (ravenrs-widgets): pages, zoom, thumbnails, search, export, print
        ├── ReportDesigner         (on the Ribbon): bands, field list, properties, drag and drop, undo/redo
        └── ravenrs-report-server  HTTP: POST a definition + data, get PDF/XLSX back
```

`ravenrs-report` has no GPU or window dependency, so it runs in servers and tests. Text is measured with the same Parley stack as the UI, so the viewer and the PDF agree to the point.

## Report model

* **Page.** Size (A4, Letter, Legal, custom), orientation, margins, watermark (text or image).
* **Bands.**
  * Report: Report Header and Report Footer.
  * Page: Page Header and Page Footer.
  * Groups: Group Header and Group Footer, nested, each with its group field and sort.
  * Detail.
  * Detail Report: master-detail with its own bands, related by key.
  * Band behavior:
    * Keep-together, page break before and after.
    * "Repeat on every page" for headers.
    * Print on first page / last page.
* **Controls.**
  * Text and data:
    * Label, with static text or an expression.
    * Rich Text: simple markup — bold, italic, links, lists.
    * Check Box.
    * Page Info: page `n` of `N`, date, user.
  * Containers:
    * Table, with rows, cells and spans.
    * Panel.
    * Sub-report.
    * Cross-band line and box.
    * Table of contents.
  * Graphics: Picture (PNG, JPEG, SVG), Line, Shape.
  * Barcodes: Code 128, Code 39, EAN-13, EAN-8, UPC-A, ITF, QR, Data Matrix, PDF417.
  * Data visualization:
    * Chart: bar, line, area, pie, doughnut, scatter.
    * Sparkline.
    * Gauge.
    * Cross Tab (pivot).
* **Expressions.** A small, documented language close to DevExpress Criteria:
  * Fields and parameters: `[Price] * [Quantity]`, `?Customer`.
  * Conditionals: `Iif([Total] > 1000, 'VIP', 'Regular')`.
  * Aggregates: `Sum([Total])`, `Count()`, `Avg`, `Min`, `Max`, `RunningSum`, scoped to group, page or report.
  * Text and dates: `FormatString('{0:C}', [Total])`, `Today()`, `AddDays`, `Concat`, `Upper` and others.
  * Expressions drive visibility, formatting rules (conditional styles), sorting, filtering and calculated fields.
* **Parameters.**
  * Kinds: typed values (text, number, date, boolean, list).
  * Defaults, required flags and multi-value parameters.
  * The viewer shows a parameter panel.
* **Styles.** Named styles, odd/even rows, conditional formatting. Built-in themes follow the RavenRS tokens and print well.
* **Localization.** Number, date and currency formats per culture (pt-BR first-class); report strings can be translated.

## Data

1. **JSON and Rust structs** (anything `serde::Serialize`), with nested arrays for master-detail.
2. **SQL:** PostgreSQL, MySQL and SQL Server. Each source has queries with parameters, and the report binds to their results. This lives behind a `sql` feature, so the WebAssembly build stays small.
3. **CSV and Excel files.**
4. **Federation:** join several sources and define master-detail relationships between them.

## Delivery phases

Each phase ends with tests, docs, gallery demos and `scripts/check.sh` green, like every RavenRS feature.

| Phase | Delivers | Done when |
|---|---|---|
| **R1 — Engine** | Report model + JSON format + Rust builder, expressions, parameters, bands, groups, sorting, filtering, summaries, master-detail, pagination, Label/Table/Picture/Line/Shape/CheckBox/PageInfo/Panel, styles, pt-BR formats | An invoice and a grouped sales report paginate correctly over 10,000 rows in < 300 ms; golden tests on the `Document` |
| **R2 — PDF and viewer** | PDF export with embedded fonts, links and outline; `DocumentViewer` widget (zoom, fit, thumbnails, search, parameter panel, export buttons) on desktop and web | The PDF opens identically in Acrobat, Chrome and Preview; the viewer shows the same pages |
| **R3 — More output and controls** | XLSX, CSV, HTML, SVG/PNG export; barcodes; charts and sparklines; sub-reports; table of contents; watermarks | Each exporter has golden tests; barcodes decode with a scanner library |
| **R4 — Designer** | End-user designer on the `Ribbon`: report explorer, field list, band surface with snapping, property grid, expression editor, drag and drop, undo/redo, preview, save/load JSON, wizards (table report, labels, invoice) | A user can build the R1 invoice from scratch without code |
| **R5 — Server and data** | `ravenrs-report-server` (HTTP API: render, template storage, parameters), SQL/CSV/XLSX sources, Cross Tab, PDF/A and digital signatures | Another system can POST JSON and receive a PDF; load-tested |

## Decisions

* **Own engine, not a port.** The model follows DevExpress concepts (bands, criteria-style expressions) so users feel at home, but the format is JSON and the code is ours.
* **`pdf-writer` + `subsetter`** (MIT/Apache, used by Typst) instead of a homemade PDF serializer: proven output, small, no C dependencies.
* **`rust_xlsxwriter`** (MIT/Apache) for XLSX.
* **Points (1/72 in) as the document unit;** the viewer scales to the screen.
* **Layout separate from rendering:** the paginator produces a `Document` once, and the viewer and every exporter consume it, so they cannot drift apart.
